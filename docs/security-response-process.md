# 人工举报、事件处置与依法协助流程

状态：2026-11-05 编写的操作规程，随本 PR 审查；没有在生产执行，也不表示已经完成任何机关要求的协助。具体命令见 security-runtime.md，备份/恢复见 security-operations.md。

1. 接收：公开邮箱 qiutian0808@163.com 接收举报及个人信息查询、更正、删除申请。请举报人提供游戏名、使用的国内或Cloudflare入口、房间码、消息编号、发生时间和简要原因；避免发送身份证、访问凭据或不相关隐私。邮箱是人工渠道，没有工单后台或自动审核。
2. 核实：站长从自己的受保护管理设备进入对应游戏及后端。只有配置的独立站长凭据可以调用管理工具；房主和普通玩家不能获得这项权限。先核对指定内容，避免批量读取无关房间或手牌。已经从短期聊天窗口滚出且没有被保全的内容可能无法恢复，不作保证。
3. 控制传播：按证据定位消息编号并隐藏，必要时限制对应房间成员或关闭房间。记录 UTC 处置时间、操作者标识、目标、原因、结果。在线广播、刷新重连和重启恢复都应核对。限制是针对现有随机成员身份，清除浏览器身份后重新加入的绕过风险仍存在，不能称为完成实名封禁。
4. 保全：如涉及违法信息、争议或有权机关要求，立即对必要记录设保全，并在受限位置保存相关证据和校验值。填写范围、原因、依据、开始时间、复核负责人；不要因磁盘告警删掉未到期或保全记录。不把所有正常聊天都改成长年保存。保全解除须记录原因和权限依据；具体处置证据期限向受理单位确认。
5. 主管部门报告与协助：核实对方机关、人员、文书、法定权限、范围、目的、接收渠道和期限；有疑义通过机关公开渠道核验。只有本人/授权管理人可以在管理端提取限定时间和房间/成员的必要记录，不通过玩家公开接口交付。依法及时处理，避免把确认流程用作拖延；是否需要立即报告按事件和主管部门要求处理。
6. 交付留痕：在受保护的操作台账记录请求来源、核验方法、授权范围、导出条件、数据项/数量、文件SHA-256、交接时间/渠道/接收人和经办人。原始文书和包含个人信息的台账保存在仓库以外；公开仓库不放机关联系方式、证件、账号秘密或导出数据。应用的站长操作日志不能替代这份实际交接台账。
7. 恢复：从备份恢复先隔离运行，核对数据库完整性及最新隐藏/限制/关闭记录，补回备份之后的处置结果；确认不会重新公开被隐藏内容才开放。旧版本不知道处置规则时，不能直接切回后开放聊天。云恢复只能在批准的维护窗口按平台实际能力操作。
8. 复核：定期查看日志告警、保全、备份可恢复性及邮箱；发生写入失败时处理存储故障并确认必要记录可以写入后恢复新内容发布。生产首次部署后应做一次两后端人工演练并记录结果；本次未代替站长处理真实举报。
