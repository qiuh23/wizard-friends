# 可复用经验

保存可跨项目复用的方法、踩坑经验和待验证想法，注明适用边界与出处。没有新发现时保持不变。

## K-001 · 视觉对比度须检查最终 CSS 级联
- 来源：2026-10-21 卡牌与获胜提示调整。共享 SVG 配色会同步影响手牌、二维和三维材质，但手牌等待状态还会受到 cinematic.css 与 clarity.css 的不同去色和亮度滤镜影响。
- WebGL 获胜标签的旧选择器包含 body 状态、has-webgl 和 winner，优先级高于普通获胜样式；只改变前景色会留下旧深底，反而变得难读。最终同时覆盖二维和 WebGL 标签的背景、文字及边框。
- 可复用做法：按真实 disabled、WebGL 和手机状态拍截图，检查实际级联，而不是只看配色常量或某一层样式。获胜标记同时使用颜色、边框与「获胜」文字，不只依赖色相。
- 2026-10-21 用户进一步明确等待时也要完整牌面亮度：禁用操作与视觉可读性应分开，使用可出牌金边表示权限。最终同时去掉基础卡牌、手牌及禁用悬停的压暗滤镜；只改桌面材质颜色，避免全画布滤镜连牌面一起变暗。

## K-002 · 聊天锚点与无框手牌的级联边界
- 来源：2026-10-29 [玩法与牌桌审查](../rules-audit-2026-10-29.md)。面板与按钮应共用实际定位容器，避免大厅、桌面和横屏分别维护固定坐标。将聊天移入按钮容器后，按钮样式须限定直接子元素，避免影响发送／关闭按钮；重绘时只替换触发按钮，保留输入节点及焦点。
- 父节点 `visibility:hidden` 可能被子角标的 `visibility:visible` 穿透；聊天展开让出手牌时用 `display:none`。去框还需清理装饰伪元素，不只删除容器 border/background。全局动画的覆盖只应包含动画属性，避免较高优先级顺带覆盖手机宽度。
- 有负重叠边距的横向手牌必须单独重置第一张牌的左边距，否则去掉外框内边距后，原生滚动到零仍可能裁掉第一张牌。验证实际触控和点击，不用强制点击绕过遮挡。
- 键盘只缩小 visual viewport 时，原按钮锚点可能把面板抬到浏览器顶栏后；只移动底部坐标不能保证输入可见。须结合 `height`、`offsetTop` 和布局高度约束整个面板，也覆盖布局视口一起缩小的情况。极低高度时检查输入、发送、关闭三者的实际边界和互相遮挡，不能只检查中心点可点击。采用的尺寸及验证证据见 [D-018](DECISIONS.md#d-018)、[H-024](HISTORY.md#h-024)。

## K-003 · 三维主牌的可测占位与实际投影
- 来源：2026-10-29 [头像化与主牌调整](DECISIONS.md#d-016)。需要保留二维卡牌占位供三维测量时，`visibility:hidden` 只隐藏父元素不够；原 `.corner { visibility:visible }` 会穿透，形成看似与牌分离的数字。应明确隐藏整棵主牌 DOM 子树，并读取角标的最终 computed visibility 验证。
- 主牌安全范围须覆盖旋转、悬浮与视角，不能只检查静止卡中心或二维外框。用 DOM 玩家／行动／出牌的实际边界寻找空位，再由摄像机反投影三维位置，按包围范围缩放。牌面单独朝向摄像机，可保留牌桌视角和席位而改善手机可读性；手机缩放与悬浮幅度一起缩放。
- 多场景共用有计时的牌局样本时，每个独立浏览器场景须设置自己的开始时刻。复用脚本启动时的 `turnDeadline` 会使后面的场景一载入就超时，导致选牌控件在点击前消失；不应为此放宽应用规则或强制点击。

## K-004 · 动画进度与公开房间摘要的阶段边界
- 来源：[H-023](HISTORY.md#h-023)，采用的时钟和目录规则见 [D-017](DECISIONS.md#d-017)。独立计时和按帧累乘会随帧率、后台挂起及重绘漂移；视觉进度应按稳定卡牌身份保留，收牌使用服务端阶段截止时间。暂停期间同步聊天、改变布局或刷新，都须检查实际缩放、透明度和剩余时间，而不只检查最终牌局状态。
- 重建 DOM 时只给一次性事件加 CSS 类会打断入场；每次新建节点重放整段动画又会倒退。应恢复既有时钟进度，同时禁止恢复快照重播历史事件。画布尺寸未变时避免重复 `setSize`，布局后立即画一帧，减少 DOM 已更新但画布尚空的窗口。
- 新大厅的 `maxRounds` 尚未设置，重开大厅也可能残留旧值；公开摘要应按阶段规范化，不直接套用进行中牌局的轮次校验。在线人数通过只能证明 presence 通道正常，不能代替等待房发布、目录按钮与实际加入的端到端检查。

## K-005 · 验收实际遮挡面积与完整可见消息
- 来源：[H-025](HISTORY.md#h-025)。牌面黑底须分别验收真实 HTML 手牌和三维纹理；仅缩纹理中的整体矩形，不能证明手牌的背景或符号右侧空白已消失。分别给数字与符号衬底，让外层透明，能够保留字号并露出插画。Canvas 用 `actualBoundingBoxLeft/Right/Ascent/Descent` 计算字形包围和基线，包含衬线外伸，不能只用字符推进宽度。
- 聊天消息上限、容器高度和文字行高共同决定可见数量。DOM 内存在 6 个气泡不代表用户能看到 6 条；须逐条检查上下边界均在裁切容器内，展开记录也一样。覆盖长短正文、手机横屏、关闭按钮占位和输入区，区分完整记录与气泡摘要；复用 [K-002](#k-002) 的焦点／键盘约束。

## K-006 · 飞牌检查要同时核对归属、布局与动画坐标
- 后续布局约束以 [D-023](DECISIONS.md#d-023) 为准：用户已允许紧凑横屏单行，原方向断言只适用于仍采用围桌方向归属的方案，不能阻止明确授权的新布局。
- 来源：[H-026](HISTORY.md#h-026)，最终显示优先级见 [D-020](DECISIONS.md#d-020)。横屏按座位编号铺整屏百分比，会使左侧玩家的牌出现在中央、右侧牌过远；只检查牌没有出屏或互相遮挡，不能证明用户能判断归属。应同时检查真实头像、姓名、颜色对应及完整墩的整体观感；大牌也可能降低可读性。
- 动画中的 `getBoundingClientRect()` 包含子卡的位移／缩放，不能拿它重新生成动画终点。使用静止的座位容器边界和卡牌布局尺寸，HTML 与 WebGL 共用同一像素坐标；收牌目的地直接取赢家头像，避免固定圈坐标、vw/dvh 与局部容器混算。
- 全体座位需从第一张牌前就预留。窄屏求空位时先去重候选，再按当前剩余选项最少的座位搜索；成对调整只是位置优化，仍不能保证归属。用户随后截图证实牌可被挪到相邻头像下，故增加 [D-021](DECISIONS.md#d-021) 的方向归属硬约束；必须同时保留遮挡、边界与向内的位置约束，不能放宽断言掩盖失败。
- 顶部头像与中央主牌之间没有足够高度时，只缩小主牌但固定中心仍可能无解；缩小后须重新寻找主牌位置。细连接线应截在玩家完整信息框和卡牌边界之外，避免穿过头像下方的赢／估数字。
- 本轮再次遇到旧 Vite 进程返回旧 CSS：核对实际 HTTP 响应后启用独立 5180 开发服务，再验收真实 computed style。浏览器页面崩溃的中断检查不算通过；独立重跑完整检查，保留模拟设备与真实手机 GPU／键盘之间的边界。

## K-007 · 连续视觉修订要用独立版本的效果图
- 来源：[H-028](HISTORY.md#h-028)。反复覆盖同名截图并复用同一链接，不能保证用户打开的是新图。修订效果图使用带代码版本／场景的新文件名，并直接展示；核对实际送达的预览后再判断视觉修复是否完成。
- 用户截图与当前文件不同时，先比较受影响区域和对应 Git 版本。可以在内存中缩放、平移模板来分析；这不改动原图。图像匹配只能确认内容来源，不能据此断言客户端具体缓存机制。

## K-008 · 首帧纹理和真正的慢图验收
- 来源：[H-030](HISTORY.md#h-030)，采用方案见 [D-022](DECISIONS.md#d-022)。TextureLoader 在网络完成前返回的纹理没有有效图片，直接挂到可见材质会出现黑面。应同步创建有完整像素和身份标记的纹理，再在解码完成后替换内容；HTML 背景也须有可读的底色。
- 共用插画的牌按资源 URL 去重，不能按牌 ID 重复下载和解码。加载失败的 Promise 要移出请求缓存，页面必须消费错误并保留可读的回退牌面。不为一次出牌同步处理全副插画；[D-030](DECISIONS.md#d-030) 后在等待阶段分批预热完整 CPU 牌面，GPU 仍按实际使用创建。
- Promise 已完成不等于新建纹理的同步首帧已完整；缓存应同步提供已解码图片／已绘制 Canvas。已有 GPU 纹理首次失败后，后台重试重画共享 Canvas 还需通知纹理 needsUpdate；一次性订阅保留到成功，并在纹理销毁时释放。相关真实慢图、失败重试及轮间证据见 [H-041](HISTORY.md#h-041)。
- Vite 的 SVG 请求既可能是实际图片，也可能是带 `?import` 的 JavaScript URL 模块。模拟慢图只挂起 `resourceType === 'image'` 的请求；把模块也拦住会阻塞 DOMContentLoaded，不能当作产品图片渲染失败。验收同时检查 Canvas 像素、实际 WebGL 像素、HTML 背景、资源请求数和图片失败分支。
- 领先牌放大后，要测实际三维投影／二维变换后的牌框，不能只测没变大的座位容器。紧凑布局补充候选位置时继续保留方向和不遮挡断言；短暂停下收牌后，比较实际 DOM 变换和透明度，而非仅检查 CSS 动画是否 paused。

## K-009 · 共享布局尺寸必须验证到实际牌面及可点击控件
- 来源：[H-032](HISTORY.md#h-032)，采用方案见 [D-023](DECISIONS.md#d-023)。设置 `--played-width` 不代表真实牌面采用该宽度：旧的 `.has-webgl .played-cards.compact-trick` 选择器可在 850px 两侧继续覆盖它。除测实体投影外，同时比较 DOM 静止牌宽与共享变量，避免实际牌只有 40px、标签却按大槽位占位。
- 主牌有限旋转应按实际转角、实体厚度及悬浮范围计算包围；使用整张牌宽作为深度的全旋转方盒会把 82px 锚点中的实体缩到约 47px。可辨识程度以实体尺寸和截图为依据，不把任意填充比例阈值当成用户要求。
- 结算按钮要在任何 Playwright 点击／自动滚动前检查视口边界、`scrollY` 及 `elementFromPoint`，展开详情后再查。公开牌和姓名条分别检查手牌、状态、按钮、聊天的遮挡；只测牌框不够。
- 运行中的 Vite HMR 会清空仅供浏览器测试的临时状态，造成“共享状态有牌、DOM 无牌”的环境中断。源码冻结后重跑，必要时记录页面加载标识，不能放宽张数断言掩盖重载。手机视口及工具栏占高模拟不等于真机验收。

## K-010 · 顶栏入口与弹层不能只移动其一
- 来源：[H-034](HISTORY.md#h-034)，采用方案见 [D-024](DECISIONS.md#d-024)。把聊天入口从底部移到顶部后，旧的相对 bottom:100% 弹层会向视口外展开；left:0 也可能因触发器靠右而横向越界。应一起调整展开方向、屏幕锚点及限高，同时保留键盘 compact 布局的覆盖优先级。
- Playwright 的 visible／enabled 不保证按钮位于视口内。对关闭、输入与发送先检查实际边界及 elementFromPoint，再真实点击；完整联机冒烟可以捕获单场静态布局测试未打开的弹层回归。UI 重构后要同步维护 CI 入口的结果选择器，继续检查同一玩法语义，不能只修第一个超时后留下后续失效断言。

## K-011 · 一次性主牌揭示应与 DOM 重建和规则结果分离
- 来源：[H-035](HISTORY.md#h-035)，采用方案见 [D-025](DECISIONS.md#d-025)。普通 render 会重建牌桌 DOM；动画对象放在同一展示控制器并复用现有帧循环，不能每次创建 CSS 动画或按卡牌 ID 去重。同一张真实翻牌可以跨轮再次出现；使用已有房间 epoch、轮次与 round 事件序号，初次快照直接归位。
- 动画终点读取实际图标矩形；控制器不保存提示文本的异步写回回调，失效时同步删除临时节点并清空引用。系统减少动态、关闭动效、断线或窗口变化要能直接取消，不能在下一次同轮消息中重启。
- 牌面和文字要一起测遮挡。已有操作面板可能占据空桌中心，不能仅按屏幕百分比安排揭示；狭窄横屏先确保操作始终可达，再使用实际空区。截图可以短暂控制浏览器中的展示时钟，但仍需独立检验真实时间自动结束，并用真实 socket 重连覆盖恢复路径。向浏览器传入相同视口尺寸不产生 resize，不能作为中途转屏证据。

## K-012 · 昵称默认值与已恢复身份应分开处理
- 来源：[H-036](HISTORY.md#h-036)，采用方案见 [D-026](DECISIONS.md#d-026)。练习和联机添加机器人均通过 src/game.js 的 addPlayer；在共享入口按 bot 分流，才能让客户端与权威服务保存相同策略的名字。只过滤显示尾码会保留旧存储值和不一致的缩略名。
- 新真人必填时，应在新建入口校验，并让已有认证的返回路径读取原权威状态。首页清除旧自动昵称偏好不能触发旧对局改名，也不能令原身份因空表单无法重连。昵称查重包含所有占座玩家，与是否在线无关；名字、认证映射、ID 和配色的保存分别验证。
- 本地恢复样本不能只在当前页面写 sessionStorage 后 reload：pagehide 会把正在运行的真实牌局重新存档。应在下一页初始化时注入明确的测试样本，再检查实际恢复值；大厅 `.seat` 还包含空位占位，人数断言应数实际玩家姓名节点。
- [H-037](HISTORY.md#h-037)：昵称必填同时影响 Worker hello 协议的测试辅助。新建成员的正向测试应显式传名；无名拒绝与已有认证的无名恢复应分别验证。若握手先失败，后续权限／迁移断言可能因没有权威状态而连带报错，先核对 fatal 内容，保留各测试原本验证的拒绝原因。共享创建规则改变时应覆盖 relay-worker 测试，不能只验证规则引擎和 RoomAuthority。

## K-013 · 平台适配的持久确认与入口归属
- 来源：[H-038](HISTORY.md#h-038)。适配已有 DO 控制器时，storage.put 的返回不应先于 SQLite 真正提交发送 ready／state；在外层按房间暂存存储和 socket 输出，单条记录提交 owner、权威状态、请求回执和关闭墓碑后再放行。通过注入磁盘失败及实际 SIGKILL 检验确认与重启恢复，不能只检查 JSON 可序列化。
- 公网 HTTP 的 crypto.randomUUID 可能不存在，getRandomValues 仍可用；统一 v4 回退后必须在非 localhost、非安全上下文实际初始化与操作。构建包含 VITE_RELAY_URL 时，国内部署须以运行时显式空 relayOrigin 强制同源，不能仅换首页按钮。
- 普通 nginx -t 不读取未启用 sites-available 文件。验收该文件需临时普通主配置；/dev/stdin 可能被重读而导致 EOF。Host 使用 $http_host 才保留非默认端口，模板语法与实际 WebSocket 升级分开验证。
- 仓库 main-only 发布角色在功能分支阶段只能准备与审计，不能声称真实 GitHub OIDC 已通过。云助手使用本机账号执行成功，只证明目标用户与命令通道；自动触发开关、发布成功、外网联机、按钮启用分别记录。

## K-014 · 已检查产物与生产配置覆盖分别记账
- 来源：[H-039](HISTORY.md#h-039)。同一平台的 UI 自动化不可用、构建日志 API 权限不足，不足以推断自动构建失败。已有正式发布权限可同步已检查 main，但需隔离导出源码、核对 CI 产物摘要、保留旧版本和命名空间；不能从正在修改的功能分支部署。
- 公开 runtime JSON 可以作为受信生产配置覆盖；应记录原 ZIP 摘要、覆盖键与配置摘要，不能声称覆盖后的目录仍逐字节匹配原包。功能分支的新 UI／文档仍通过 PR。
- 重放已完成的 workflow_run 可验证新开关下的原检查事件路径而不重复构建；与新 main 提交自然触发、第二次真实版本切换分开表述。服务重启前后比较敏感状态的摘要，不输出认证映射、手牌或随机密钥。

## K-015 · 手牌关联操作和结算动画要验证真实几何与持久时钟
- 来源：[H-042](HISTORY.md#h-042)，采用方案见 [D-031](DECISIONS.md#d-031)。把 fixed 操作改成 hand-section 内的 absolute 后，展开容器的 overflow:hidden 会裁掉按钮；让外层容器可见溢出，滚动仍交给 hand-grid。实际牌面会抬起／旋转，须测变换后的牌面、身份子树和 WebGL 投影。展开按钮在手牌上缘外，也要纳入公开牌可用区域。
- 每帧由 TableMotion 写 transform 的二维牌应取消全局 button CSS transform transition，否则共享时钟已收完、透明度已归零时，真实牌面位置仍落后。对实际赢家头像校验终点，不能只看 pose.collect。
- 结算 phase 不等于有自动下一步：普通联机墩有 task deadline，练习／轮末／终局没有；收牌展示应有独立可持久截止和暂停剩余，不添加自动任务。只在页面控制器缓存 collectAt 能冻住当前页面，却无法保证暂停后刷新／服务重建；分别检查存档、重连、恢复后原进度与原结算阶段。

## K-016 · 按需绘制必须显式失效，性能计数必须说明口径
- 来源：[H-043](HISTORY.md#h-043)，采用方案见 [D-032](DECISIONS.md#d-032)。停掉永久 RAF 后，要分别请求 HTML 和 WebGL：异步纹理完成、context lost／restored、可见性返回、布局和动效偏好都不能再依赖旧循环兜底；未来收牌仍需按 TableMotion 原时间唤醒。节点缓存应在结构改变后刷新，连接线在布局中创建后也要更新缓存引用。
- 主牌控制器已有可注入 clock；新帧队列只统一调度，不应绕过原 clock 强传 RAF 时间，否则受控时钟和新一轮 start 会落入不同时间域。揭示源牌堆必须在场景／布局更新后测量。新视口样本要先等真实 resize 事件完成，再注入下一次发牌；中途 resize 取消则单独保留断言。
- 局部更新复用 HandMotion 时，old===placeholder 必须跳过替换，不能把节点自身属性清空；社交按钮原先随 app 重建而消失，改成局部刷新后需复用节点，避免重复 ID、监听或焦点丢失。
- 实测布局入口次数含缓存检查，DOM addedNodes 只计直接节点，自动化观察窗不是交互延迟。基线隔离、同浏览器／视口／画质，并区分源码判断、浏览器模拟、真实扩展恢复与系统后台行为。旧独立图形阈值失败需先在基线复现，不能直接归因本次或放宽阈值。完整数据见 H-043 的报告，不重复维护多份数值。
