# 首页竖版道具内收并恢复原视角

基线：#59 的 main `32052843e49f52b68194cc392fd70ef13f426ff8`。

用户先纠正“我的意思不是这样抬高视角”，再明确“还是尽量把元素挪到首页可看到的位置”。本轮取代 #59 的抬高视角方案，不再复用对局相机。

## 变化与保留

- 首页相机完整恢复 #58：位置 `(0, 7.3, 10.2)`、43° FOV、朝向 `(0,0,0)`，没有额外缩放或投影偏移。对局相机与灯光模块也恢复为 #58 的原文件。
- 三张首页牌的尺寸、位置、旋转与浮动恢复 #58；原 hero 灯光、外围可见性、圆环、粒子也恢复。
- 仅 ≤700px 手机竖版首页移动现有桌面道具：两侧分别排入蜡烛及左灯笼，下部留给书、水晶球、牌堆和金币。根据真实模型投影边界适量缩小道具，不新增模型、颜色、灯或动作。
- 对非蜡烛道具和程序化备用模型补齐接地，防止缩小后落入毡面下方。已导入蜡烛与灯笼仍由原灯光适配器接地。
- 顶栏、按钮、昵称、目录、加入弹窗、CSS、素材、桌面和横屏首页、候场、对局、规则与协议不改。横屏/桌面恢复原道具位置和大小。

## 自动验证

- `npm run check`、470 项全量测试、国内/海外构建、Worker dry-run 与 `git diff --check` 通过。
- 首页相机矩阵及浮牌变换与 #58 对齐，包含短竖屏与横竖切换；真实对局和候场矩阵保持不变。
- 真实 GLB 道具验证覆盖 320×480、320×568、360×640、390×568、390×844、430×932、600×700，包含普通/低画质往返、三档灯焰时刻。
- 道具完整 mesh 投影留在可见画布内，距其他道具和三张牌至少 3px；旋转牌覆盖 64 个角度及浮动上下限，三牌画布边界另覆盖 128 个角度。检查的是真实 mesh，不把地面锚点或光晕当成模型边界。
- 所有道具实体位于实际桌面木框范围，最低点不低于毡面；程序化备用场景也覆盖接地和可见边界。
- 排列最多六次迭代，每次统一更新灯光一次，加最后一次，共不超过七次；不对每个道具反复更新整个灯光系统，也不在每帧重新排版。

## 验证边界

此托管云 Chromium 的进程 socket 限制仍未解除，没有新的浏览器截图、WebGL 像素或真机验收。上述检查证明相机恢复及几何摆位/遮挡边界，不等同于真实屏幕亮度或审美验收。原渐变遮罩与色彩保持不变。没有外部配置改动或审批拒绝。
